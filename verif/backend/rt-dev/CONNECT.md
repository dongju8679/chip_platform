# rt-dev adapter connection guide

## What has to be connected
The adapter (verif_rtdev.h) only needs 4 functions wired to the company's
original engine:

```c
bool rtdev_master_write(uint32_t addr, uint32_t data);  // -> the original master_write
bool rtdev_master_read (uint32_t addr, uint32_t* data); // -> the original master_read
void rtdev_tick        (int n);                         // -> the original tick
void rtdev_trigger_irq (uint32_t id);                   // -> the original interrupt injection
```

## Where they live upstream (per import_test.py / common.cc)
- master_write/read, tick : emulator.h / interface.h (company original)
- the dispatcher run_test_sequence(testname) : generated by import_test.py

## How to connect (company environment)
Option A) RTDEV_NATIVE build:
  provide emulator.h/interface.h via -I and link directly against the original
  master_*/tick.

Option B) a wrapper implementation (recommended, 4 lines):
```c
// rtdev_bridge.c (company environment)
#include "emulator.h"
bool rtdev_master_write(uint32_t a, uint32_t d){ return master_write(a,d); }
bool rtdev_master_read (uint32_t a, uint32_t* d){ return master_read(a,*d); }
void rtdev_tick        (int n){ tick(n); }
void rtdev_trigger_irq (uint32_t id){ /* the original IRQ injection API */ }
```

## Verification
```
make -f Implementation/Makefile.VERIF src_dir=. F=CLINT SF=rtc BACKEND=rt-dev
```
Because trigger_irq is implemented upstream on rt-dev, PLIC co-sim also works
immediately:
```
make -f Implementation/Makefile.VERIF src_dir=. F=PLIC SF=latency BACKEND=rt-dev
```
